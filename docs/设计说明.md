# 设计说明

## 目标与入口

帮学助手提供本机控制面板、CLI 与 MCP，帮助用户在选定的课程范围内处理学习页面并核验进度。平台地址由本机配置，仓库不包含实际站点地址。

```
控制面板 / CLI / MCP → 范围巡检 → 单班巡检 → 课程流程 → 浏览器驱动
```

桌面版、`bangxue agent` 和 MCP 的 `bangxue_agent` 通过同一个经过认证的本机服务交互。面板工作线程串行执行登录检查、班级发现与任务操作。新任务在同一把锁内校验所选平台、栏目和班级，保存范围及运行状态，再进入巡检队列。任务结果由同一个状态接口提供。

## 完成与标签证据

每班在新建且带创建凭据的临时页读取完整分页。页码、行快照与可见总数必须一致。空表和未报名只在页面证据明确时处理，失败进入待处理。完成课程需由同名课表行确认，重名则要求人工核对。整班完成记录 `class_evidence`，包括班级 ID、完整总数和核验时间。旧完成记录需重新核验。

每个由工具打开的页面记录创建凭据。关页同时要求驱动、创建来源、目标标识和当前页面身份匹配。无法核实、地址已变化或用户手动打开的页面保留。Playwright 支持稳定目标标识。只能操作当前前台页且不能证明实际选中目标的驱动禁止关页。

## 状态与调度

`runner.py` 管理范围与当前班，待处理班级不阻断后面的班。`monitor.py` 处理单班进度、暂停与关页，`flow.py` 处理课程和页面。`control.py` 统一暂停和恢复。状态文件使用原子写和进程锁，操作前检查暂停标记。`_heartbeat.json` 记录每轮起止、进程与摘要。面板每 60 秒调度一轮，本地日志至少每 10 分钟记录一次摘要。

平台要求登录或验证码时暂停。其他课表或页面错误需处理，不宣称已完成。课程包的视频课时可以处理，互动内容或考试保留人工。播放页结尾先查课表，只有平台确认后才计完成。尚未确认时可在原任务页尝试重播。加载失败对任务自有页面至多自动恢复一次，并降低后续补位并发。无法确认倍速或播放位置时报告并等待用户处理。

## 开发与验证

依赖见 `pyproject.toml`。`site_config.py` 管理本机平台地址，`audit.py` 提供只读范围复核，`tests/` 使用模拟页面。桌面构建在对应操作系统执行 `packaging/build_desktop.py`，随后运行 `packaging/smoke_desktop.py`。
